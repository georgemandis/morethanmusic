# website

The site for More than Music with MIDI. Docs-only [Docusaurus](https://docusaurus.io) 3, dark mode by
default, laid out in ten sections: Start here, Pick your tool, the Explorer, Devices, Make your own, Helpers,
Examples, Troubleshooting, Talks and workshops, About.

## Commands

```sh
cd website
npm install              # once. A real node_modules, not a symlink: a symlink into another checkout breaks SSG
npm start                # dev server at http://localhost:3000
./refresh.sh             # re-pull code samples and README sections into docs/
node refresh.mjs devices # regenerate docs/03-devices/ from devices/<slug>/
node refresh.mjs talks   # regenerate docs/07-talks/ from talks/<slug>/
npm run build            # production build into build/
./check-links.sh         # build, lay out, serve with wrangler dev, curl every page, load every embed headless
../deploy-preview.sh     # all of that and deploy to the preview Worker
```

`npm start` does not refresh. `deploy-preview.sh` runs the includes refresh first.

## Sections

`docs/`, in sidebar order. Each folder is a category: `_category_.json` sets label, position and
whether it starts collapsed; `index.md` is the category page (Docusaurus convention); every other
page in the folder lists itself by `sidebar_position`. `sidebars.js` is one autogenerated root, so
adding a page never means editing it. Number prefixes are stripped from URLs.

| Section | Folder or file | URL |
|---|---|---|
| Start here | `00-start-here/` (index is `/`, plus the MIDI intro) | `/`, `/start-here/introduction-to-midi/` |
| Pick your tool | `01-pick-your-tool/` | `/pick-your-tool/`, then `/pick-your-tool/p5/`, `/processing-java/`, `/processing-python/`, `/something-else/` under it |
| The Explorer | `02-the-explorer.md` | `/the-explorer/` |
| Devices | `03-devices/` (`index.md` here, pages generated from `devices/`) | `/devices/<slug>/` |
| Make your own | `04-make-your-own/` | `/make-your-own/...` |
| Helpers | `05-helpers/` | `/helpers/` (pulls `midi-helpers/README.md`) |
| Examples | `06-examples/` (hello world, three bytes, ideas, demos, references) | `/examples/...` |
| Troubleshooting | `08-troubleshooting.md` | `/troubleshooting/` |
| Talks and workshops | `07-talks/` (generated from `talks/`, plus `pcd-2026-nyc.md`, hand-written; `_category_.json` position 8.5 so it follows Troubleshooting) | `/talks/...` |

The Explorer page is `/the-explorer/`, not `/explorer/`, because `/explorer/` is the repo folder
served beside the site and `/explorer` redirects to the web edition.

`07-talks/pcd-2026-nyc.md` is the PCD 2026 workshop's own page (agenda, what to bring, day-of notes),
kept by hand. The talks generator writes `2026-pcd-nyc.md`, the compendium entry, which links to it.
The generator never deletes files, so both live in the folder.

## Pulled code and sections

A block between `{/* include: SPEC */}` and `{/* /include */}` in a doc belongs to `refresh.mjs`.
`./refresh.sh` rewrites it. `./refresh.sh --check` only reports.

- `SPEC` is a path from the repo root. `*` globs, first match wins. Write `%` for `*` when the glob
  would put `*/` inside the comment.
- A Markdown source may end in `#Heading text`: the first section whose heading contains that text,
  up to the next heading of the same or higher level. Keep those words in the source headings.
- Code files become a fenced block titled with the file name. Markdown is demoted one heading level,
  relative links become `pathname:///…`, and `{` and `<` outside code are escaped for MDX.
- A missing source or section is left alone and listed as `pending`, so the `:::warning` admonition in
  the doc stays visible.

Device pages link to other site pages through `devices/links.json` (`@explorer`, `@hello-world`,
`@p5-editor`, `@raw-intro`, `@ideas`, `@demos`). When a URL moves, change it there and run
`node refresh.mjs devices`.

## Live p5 sketches

`src/components/LiveSketch.js` embeds a sketch in an iframe with `allow="midi *"` inside a 16:9 box.
It reads the canvas size p5 created (same origin) and scales the frame to fit.

```mdx
import LiveSketch from '@site/src/components/LiveSketch';

<LiveSketch src="/starters/p5/pipsqueak/" title="PipSqueak starter, p5.js" />
```

Those paths exist in production because `deploy-preview.sh` lays the repo folders beside the build.
For `npm start`, `link-repo.mjs` (`prestart`) fills `.repo-links/` with a symlink to every top-level
repo folder except `website`, `site`, `docs`, `pcd2026` and `node_modules`, and the config lists
`.repo-links` as a second static directory. Before `npm run build` it runs with `--empty` and leaves
the folder empty, because Docusaurus would otherwise copy every linked folder into `build/` wholesale,
local build output included; `build-site.sh` lays the folders out instead. `.repo-links` is git-ignored.

## Redirects

`static/_redirects` is read by the Worker before it serves assets. It keeps the short paths from
the 2026 deck (`/explorer`, `/helpers.js`, `/projects-live`, `/examples/<device>`) and sends every
URL of the PCD 2026 workshop site to its new home (`/before-you-start/` to `/`, `/your-device/*` to
`/devices/*`, `/hello-world/` to `/examples/hello-world/` and so on). `check-links.sh` follows each
one and fails if the target is not a page.

## check-links.sh

Builds and lays out with `../build-site.sh`, serves `build/` with
`wrangler dev -c wrangler.preview.jsonc` so `_redirects` applies, then curls every URL in the
sitemap, the ten section URLs, the old URLs (and checks where each lands), every `pathname:///` link
into the repo folders and every `LiveSketch` src, following redirects, and fails on anything that
does not end on a 2xx. It checks the sidebar lists the ten sections in order, and that paths that must not be served (planning notes, build output, personal files) return 404. Then
`check-embeds.mjs` self-tests and loads every embedded sketch and six doc pages in headless Chrome
over the DevTools protocol; a page fails if it never fires load or logs anything. A missing Chrome
fails the run; `SKIP_CHROME=1` skips that step on purpose. `--no-build` reuses the build that is
there; `PORT` picks the port (default 8799). The build itself fails on a broken link or anchor
(`onBrokenLinks: 'throw'`).

## Deployment

Three Workers, three configs:

| | Config | Script | Serves |
|---|---|---|---|
| morethanmusic.dev | `wrangler.jsonc` (`morethanmusic`, custom domain) | `deploy.sh` | this site |
| Preview | `wrangler.preview.jsonc` (`morethanmusic-preview`, workers.dev only) | `deploy-preview.sh` | this site, for a look before deploying |
| pcd2026.mand.is | `pcd2026/wrangler.jsonc` (`pcd-midi-workshop`) | `pcd2026/deploy.sh` | a 301 to morethanmusic.dev; `/` goes to the PCD talk entry. `node pcd2026/test.mjs` |

`build-site.sh` is the shared first step: it refreshes the includes, builds, merges every top-level
repo folder except `website`, `node_modules`, `docs` (planning), `pcd2026` and `site` (the retired
hand-built workshop site) into `build/` with `rsync --ignore-existing` (so `devices/` and `talks/`
land beside the `/devices/` and `/talks/` pages without replacing them), copies loose root files that
do not shadow the site's own, and copies `.assetsignore`. The deploy scripts run it and then
`wrangler deploy` with their config. The live site is built by Cloudflare Workers Builds from the
`main` branch of the public repo, with the build command `cd website && npm ci && cd .. && ./build-site.sh`
and the default deploy command, so a push to `main` is a deploy. CI on GitHub runs the helper test
suites and a site build on every push.

Plausible is in `headTags` and only loads when `location.hostname` is `morethanmusic.dev`.

## Decisions

- Start here is the home page at `/`. The plan's `/start-here/` and `/before-you-start/` both redirect
  to `/`. The MIDI intro moved next to it as `/start-here/introduction-to-midi/`.
- The Examples section owns `/examples/`. The old `/examples/*` shortcut into `starters/p5/` is kept
  for the five device names only; `/projects-live` goes to the demos page, since `projects/p5/` has no
  index page and used to 404.
- The GitHub links point at `georgemandis/morethanmusic`, the public repo (the renamed workshop repo;
  the old name redirects). `publish.sh` mirrors this working repo into it.
- The Helpers page pulls `midi-helpers/README.md#Install` and `#In the IDE`, so the registry READMEs
  can link to `/helpers/` and the page stays in step with the helpers' own README.
- Licence, decided 2026-10-11: MIT for code (`LICENSE` at the root, same text as `midi-helpers/LICENSE`
  and the firmware folders), CC BY 4.0 for text and photos (`LICENSE-CONTENT.txt`). The About page says so.
- Troubleshooting repeats facts from the READMEs in one place. When a README changes,
  the matching line here is edited by hand.
- Slides are not on the site. The deck and its sketch stay in `slides/`.
- `website/node_modules` must be a real install. A worktree with a symlink into another checkout's
  `node_modules` builds the client bundle but every doc page fails static rendering with `Cannot read
  properties of undefined (reading 'id')`; `npm ci` in the worktree fixes it.
